# 10. PWA и мобильная версия

## 10.1. Что даёт PWA

* **Установка на телефон/ПК** без магазинов приложений: Android (Chrome/Edge/Samsung Internet) и desktop показывают
  системный диалог установки, на iOS работает «Поделиться → На экран „Домой“». Приложение само предлагает установку
  баннером (`src/components/PwaProvider.tsx`); отказ запоминается на 7 дней в `localStorage`.
* **Офлайн-режим на чтение**: последние открытые страницы и ответы `GET /api/v1/*` хранятся в Cache Storage.
  Без сети показываются сохранённые данные (с жёлтой полосой «Нет подключения»), а мутации получают понятную
  ошибку `503 OFFLINE`, а не `TypeError: Failed to fetch`.
* **Бесшовные обновления**: новая версия service worker устанавливается в фоне; пользователю показывается
  карточка «Доступно обновление → Обновить». При возврате в приложение проверка обновлений выполняется повторно.
* **Ярлыки** (long-press по иконке на Android / ПКМ на desktop): «Новая заявка», «Заявки», «Моя бригада».

## 10.2. Файлы

| Файл | Назначение |
|---|---|
| `public/manifest.webmanifest` | Манифест: имя, цвета, иконки `any` + `maskable`, `shortcuts`, `display_override`. |
| `public/sw.js` | Service worker (стратегии — ниже). Версия кэша — константа `VERSION`; **меняйте её при выпуске**, чтобы старые кэши удалились. |
| `public/icons/*` | Иконки. Генерируются из `icon.svg`: `node scripts/gen-icons.mjs` (нужен `sharp`, он ставится вместе с Next). |
| `src/components/PwaProvider.tsx` | Регистрация SW, баннер установки, карточка обновления, индикатор офлайна. |
| `src/app/offline/` | Страница-заглушка, когда страницы нет в кэше; при появлении сети перезагружается сама. |
| `next.config.ts` | Заголовки: `sw.js` без HTTP-кэша, иконки — `immutable`, базовые security-заголовки. |

## 10.3. Стратегии кэширования

| Ресурс | Стратегия | Кэш |
|---|---|---|
| `/_next/static/*`, `/icons/*`, шрифты | cache-first (иммутабельные по хэшу) | `fsm-vN-static` |
| Навигация (HTML) | network-first с таймаутом 6 с → кэш → `/offline`. Ответы-редиректы (на `/login`) не кэшируются. | `fsm-vN-pages` (≤ 60) |
| `GET /api/v1/*` | network-first с таймаутом 10 с → кэш с заголовком `X-SW-Cache: 1` → `503 OFFLINE` | `fsm-vN-api` (≤ 120) |
| Опрос чата (`?afterId=`), `/api/health`, `/api/v1/auth/*` | только сеть | — |
| `POST/PATCH/DELETE` | только сеть; офлайн → `503 {code:"OFFLINE"}` | — |

При выходе из аккаунта клиент отправляет SW сообщение `CLEAR_DATA_CACHE`, и кэши страниц/API очищаются — следующий
пользователь на том же устройстве не увидит чужие данные.

Обработчики `push` / `notificationclick` уже есть в SW — это заготовка под Web Push из roadmap; серверная часть
(подписки, VAPID) пока не реализована.

## 10.4. Мобильный интерфейс

* **Нижняя навигация**: до 4 основных разделов + «Ещё» — шторка со всеми разделами, профилем и выходом.
  Раньше разделы после пятого были недоступны с телефона.
* **Шапка**: кнопка «Назад» на вложенных экранах (карточка заявки, объект, бригада…), аватар с меню профиля.
  Учитываются safe-area (чёлка/жест-бар) в standalone-режиме.
* **Список заявок**: горизонтальные чипы быстрых фильтров (Все / Открытые / Просроченные / по статусу), поиск и фильтр
  по бригаде спрятаны в раскрывающийся блок; карточки с подсветкой просрочки; плавающая кнопка «+ Заявка».
* **Карточка заявки**: порядок блоков на телефоне — Информация → **Действия** → Работы → Материалы → Чат → История
  (монтажнику не нужно листать вниз, чтобы сменить статус). Кнопки «📍 Маршрут» (Яндекс.Карты) и «📞 Позвонить на объект».
* **Формы**: поля 16 px на мобильных (iOS не увеличивает страницу при фокусе), кнопки ≥ 40 px, `inputMode`/`enterKeyHint`
  для подходящей клавиатуры, демо-доступы на странице входа подставляются одним нажатием.
* Иконки навигации — SVG (`src/components/icons.tsx`), а не unicode-символы, которые на Android/iOS рисовались по-разному.

## 10.5. Проверка

1. Откройте сайт по HTTPS (или `localhost`) в Chrome → DevTools → *Application → Manifest*: нет предупреждений,
   иконки `any` и `maskable` показаны. *Service Workers*: статус `activated`.
2. Включите *Network → Offline*, обновите открытую ранее страницу — она должна загрузиться из кэша с жёлтой полосой.
3. Lighthouse → категория PWA/«Installable» — без блокирующих замечаний.
4. Измените `VERSION` в `sw.js`, задеплойте, откройте приложение — появится карточка «Доступно обновление».
