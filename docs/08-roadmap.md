# 8. План дальнейшего развития

## 8.1. Готовность архитектуры к нативным Android/iOS-приложениям

Уже заложено:
- **Чистый REST API `/api/v1`** с единым форматом ответов и кодами ошибок; вся бизнес-логика — в сервисном слое, а не в UI.
- **Bearer-токен**: `POST /auth/login` возвращает `token`; любой эндпоинт принимает `Authorization: Bearer`. Мобильному клиенту не нужны cookie.
- **Версионирование по URL** — можно выпускать `/api/v2`, не ломая установленные приложения.
- **Область видимости на сервере** (своя бригада / свой клиент) — мобильный клиент не может получить лишние данные даже при ошибке в UI.
- **Идемпотентные по смыслу операции** с проверками состояния (409) — безопасны при повторной отправке после потери сети.

## 8.2. Офлайн-режим для нативных приложений (следующие итерации)

1. **Синхронизация «вниз»**: добавить `GET /api/v1/sync?since=<timestamp>` с дельтами по заявкам бригады, остаткам и справочникам (поле `updated_at` уже есть у `tickets`, `equipment_units`, `stock_balances`; добавить у остальных).
2. **Очередь операций «вверх»**: клиент хранит очередь `{op, payload, clientOpId}`; сервер принимает `Idempotency-Key`/`clientOpId` и хранит таблицу `client_operations` для дедупликации.
3. **Разрешение конфликтов**: для статусов заявки — по матрице переходов (сервер отклонит недопустимый переход, клиент покажет актуальное состояние); для склада — серверные проверки остатков являются финальными.
4. **Вложения**: фото акта/монтажа — `ticket_attachments` + S3-совместимое хранилище (MinIO в том же compose) с отложенной загрузкой.
5. **Push-уведомления** о назначении/изменении заявки (FCM/APNs), Web Push для PWA.

## 8.3. Функциональные расширения

- Refresh-токены и отзыв сессий (таблица `sessions`), 2FA для администраторов.
- Календарь/диспетчерская доска (drag-and-drop выездов по бригадам), геолокация и маршруты.
- Регламентное ТО: договоры обслуживания и автогенерация периодических заявок.
- Печатные формы: акт выполненных работ, накладная на отгрузку бригаде.
- Сканирование штрих-кодов/QR серийных номеров камерой телефона при приходе и установке.
- Гарантийный учёт по серийным единицам (срок гарантии, история ремонтов, замена по гарантии — новый тип операции `replace`).
- Инвентаризация: сверка фактических остатков бригады с учётными, акты расхождений.
- Экспорт отчётов в XLSX/CSV, интеграция с 1С (обмен номенклатурой и документами).
- Аудит-лог действий пользователей, SLA-таймеры по приоритетам.

## 8.4. Технический долг / эксплуатация

- Перейти с `drizzle-kit push` на версионированные SQL-миграции (`db:generate`/`db:migrate`) в проде.
- Rate limiting на `/auth/login`, CSP-заголовки.
- Тесты: unit для сервисов (машина состояний, движение запасов), e2e для ключевых сценариев.
- Мониторинг: `/api/health` + Prometheus-экспортёр PostgreSQL, алерты на просроченные заявки.
